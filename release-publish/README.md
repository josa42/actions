# release-publish

Create the GitHub release of a tag and upload its assets. Usually runs after
[release-prepare][].

## Usage

```yaml
- uses: actions/checkout@v5
  with:
    ref: ${{ needs.prepare.outputs.tag }}

- run: zip -r dist.zip dist

- uses: josa42/actions/release-publish@dist
  with:
    tag: ${{ needs.prepare.outputs.tag }}
    notes: ${{ needs.prepare.outputs.notes }}
    files: dist.zip
```

The job needs `contents: write`.

## Inputs

| Input          | Default               | Description                                       |
| -------------- | --------------------- | ------------------------------------------------- |
| `tag`          |                       | Tag of the release                                |
| `notes`        |                       | Release notes, generated by GitHub when empty     |
| `files`        |                       | Path patterns of files to upload, one per line    |
| `draft`        | `false`               | Create a draft release                            |
| `prerelease`   | `false`               | Mark the release as a pre-release                 |
| `github-token` | `${{ github.token }}` | Token for the GitHub API                          |

## Outputs

| Output | Description |
| ------ | ----------- |
| `id`   | Release ID  |
| `url`  | Release URL |

## Assets

`files` uses the [path patterns][patterns] of get-changed-files, relative to
the working directory. Each pattern must match at least one file, and assets
are named by file name alone, so two matches with the same name fail.

## Re-running

Publishing is safe to repeat. An existing release of the tag is updated
instead of duplicated, and assets of the same name are replaced. If an upload
fails, re-run the failed job.

Updating keeps the current release notes unless `notes` is set.
